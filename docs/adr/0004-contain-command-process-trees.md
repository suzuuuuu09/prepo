# Contain command process trees

Run every command check inside an OS-level process container so timeout or observation-limit cancellation terminates normal descendant processes, using process groups on Unix and Job Objects on Windows. The Active Command registry and cleanup state belong to one Run, never to a process-wide global. If containment cannot be established, do not start the command and return `CheckOutcome::Error`; if termination cannot be confirmed, return `Error` with a prominent warning that processes may remain. This platform-specific complexity is required because killing only the direct child could leave descendants running after a diagnostic completes.

On Windows, create the process in a suspended state, assign it to the Job Object, and resume its primary thread only after assignment succeeds. If any step after process creation fails, do not resume the process and perform cleanup. On both platforms, a private reaper exclusively owns direct-child collection; cancellation of a check evaluation must not make an Active Command unreachable. A normal lifecycle completion disarms containment even when the Check Outcome is Failed, while a disarm or termination-confirmation failure is `Error` with `command_cleanup_failed`.

The command module exposes only the Run-scoped `CommandRunner`, `CommandControl`, and `CommandCleanup` handles: evaluate a validated command, begin or force the one cleanup batch, and wait for its shared result. OS-specific containment and registry state remain private to that module.

Check runs install interruption handlers before scheduling. The main supervisor gives a ready signal priority over engine completion. The first Ctrl-C or Unix SIGTERM discards the engine result, stops scheduling, cancels network operations, terminates the one Run-scoped cleanup batch, waits up to five seconds from the stop request, emits no partial result, and exits with 130 or 143 respectively. A second signal re-sends best-effort termination to the same batch and exits immediately; cleanup failure is warned about without replacing the first signal-derived exit code.

This is containment for trusted commands, not an adversarial sandbox. A process that deliberately escapes its Unix process group or otherwise evades the OS container is outside the MVP threat model. Prepo verifies only the processes still owned by its container and never guesses by process name or kills unrelated system processes.
